# Безопасность XSafety

Документ описывает модель угроз статической сборки (GitHub Pages +
Firebase), защитные механизмы, найденные и исправленные дефекты и
остаточные риски. Файлы пользователя **не передаются** на сервер: проверка
идёт в браузере, в базу попадают только метаданные отчёта.

## 1. Что защищаем

| Актив | Где живёт | Кто может навредить |
|---|---|---|
| Аккаунты | Firebase Authentication | подбор пароля, перебор, фишинг |
| Профиль и тариф | Realtime Database `users/{uid}` | подмена тарифа, чужие данные |
| История отчётов | `scans/{uid}` | чтение чужих отчётов, XSS через имя файла |
| Суточные квоты | `usage/{model}` | обход лимита, гонка запросов |
| Браузер проверяющего | DOM, HTML-отчёт | XSS, подделка отчёта |
| Репозиторий | GitHub | копирование сигнатур, подмена правил |

## 2. Принципы

1. Правила базы — единственная граница доверия. Интерфейс можно обойти,
   поэтому всё, что связано с доступом, проверяют `database.rules.json`.
2. Данные из файла — недоверенные. В DOM они попадают только через
   `textContent`; HTML собирается с экранированием.
3. Файл никогда не исполняется и не покидает устройство. Архивы
   распаковываются в памяти с лимитами, PE только читается.
4. Секретов в статике нет. Веб-ключ Firebase публичен по дизайну; доступ
   ограничивают Auth и правила.
5. Ничего не считается «на глаз»: правила, лимиты и цены генерируются из
   одного источника и проверяются тестами.

## 3. Firebase: правила доступа

`database.rules.json`:

- корень закрыт (`.read: false`, `.write: false`);
- `users` читает только владелец или админ по email; админ определяется
  сравнением `auth.token.email.toLowerCase()`;
- `plan`, `planUntil`, `planOffer` валидируются по списку тарифов;
- `banned` и `createdAt` пользователь не может менять себе сам;
- `usage.$model` требует `count` и `period`; `count` может только расти
  (`>= data.val()`) или сбрасываться в `0` при новом периоде;
- `scans/$uid` доступны только владельцу (чтение — ещё и админу), запись —
  только владельцу; `filename` ≤ 300 символов, `verdict` из белого списка;
- `purchases/$uid` — история покупок, план и оффер из белого списка.

Проверить правила в эмуляторе:

```bash
firebase emulators:start --only database
```

## 4. Клиентская защита

| Риск | Механизм | Проверка |
|---|---|---|
| XSS через имя файла | только `textContent`, `el()` не умеет `innerHTML` | `test_web_ui.py` |
| XSS через evidence | `cleanText` + экранирование в HTML-отчёте | `test_report_escapes_*` |
| ZIP-бомба | лимит записи 8 МБ, всего 32 МБ, коэффициент 150:1 | `test_zip_bomb_skipped` |
| Zip-slip | архив не распаковывается на диск, имена проверяются | `test_zip_traversal_and_double_extension` |
| Вложенные архивы | глубина 2, 512 записей, бюджет байт | `test_nested_zip_is_scanned` |
| PE-бомбы | лимиты секций, импортов и функций, bounds-check | `test_pe_imports_and_injection` |
| Подмена расширения | двойная проверка: UI и движок | `test_model_rejects_foreign_extension` |
| Обход лимита | атомарная транзакция + правила базы | `test_web_ui.py`, `test_quota.py` |
| Утечка секретов в отчёте | маскирование паролей, Bearer, userinfo URL | `test_ldr_roundtrip` |
| Кэширование чужой версии | HTML без кэша, ассеты с `max-age=3600` | `firebase.json` |
| Встраивание в чужой iframe | CSP `frame-ancestors 'self' https:` | заголовок в `index.html` |

CSP сайта: `default-src 'self'`, скрипты — свои и `www.gstatic.com`
(Firebase SDK), соединения — только домены Firebase/Google, `object-src
'none'`, `base-uri 'none'`, `form-action 'self'`.

## 5. LDR: зачем сигнатуры закодированы

Паттерны и строковые маркеры хранятся в виде `L("...")` / `D("...")` и
разворачиваются при загрузке модуля. Ключ лежит в `js/core/ldr.js` и в
`xsafety/scan/ldr.py`.

- **Даёт:** правила не ищутся простым `grep`, их сложнее скопировать и
  подогнать образец под список строк.
- **Не даёт:** защиты от реверса. Это обфускация, а не шифрование.
- **Целостность:** уникальность `sig_id`, компиляция регулярок, тест на
  отсутствие открытых паттернов и тест паритета Python ↔ JS.

## 6. Найденные и исправленные дефекты

| ID | Дефект | Последствие | Исправление |
|---|---|---|---|
| D-01 | у `jar`-модуля не было `archive_findings` | падение на любом `.jar` | алиас + тест |
| D-02 | двойное LDR-кодирование | паттерны превращались в токены | `tools/ldr_normalize.py`, guard, тест |
| D-03 | история сортировалась по секундам | терялись свежие отчёты | сортировка и обрезка по `rowid` |
| D-04 | `vbs.wscript_shell` не видел `Shell.Run` без скобок | пропуск запуска | правило `vbs.shell_run_bare` |
| D-05 | PE-импорты содержали только имена DLL | пропуск инъекций | разбор thunk-таблицы |
| D-06 | скидка считалась как `(price, old_price)` | «−0%» на витрине | порядок аргументов + тест каталога |
| D-07 | `Blob.arrayBuffer` отсутствовал в старых браузерах | сканирование падало | fallback через `FileReader` |
| D-08 | Pages собирался из чужой ветки | изменения не появлялись на сайте | источник Pages переключён на рабочую ветку |
| D-09 | бандл сигнатур собирался как массив массивов | работали только правила BAT | дедупликация реестра в `index.js` |
| D-10 | двойная валидация `fileName`/`filename` в правилах | отчёт не сохранялся | имена полей выровнены |

**Урок:** любое расхождение Python и JS ловится тестом паритета на наборе
образцов (BAT, PY, JS, PS1, VBS, HTA, ZIP, JAR, DLL, EXE). Если тест
упал — на сайт нельзя пускать сборку.

## 7. Остаточные риски

1. **Квоты на клиенте.** Правила мешают уменьшать счётчик и трогать чужой
   профиль, но владелец аккаунта может сбросить свой `count` в 0 и обойти
   лимит. Жёсткий контроль — только Cloud Functions / сервер.
2. **Демо-оплата.** План пишется в профиль без проверки платежа; это
   осознанное решение для демо. Для продакшена нужен провайдер и вебхук.
3. **Публичный конфиг Firebase.** Ключ ограничивают правила и домены:
   обязательно настройте HTTP-referrer ограничения и App Check.
4. **Статический анализ** не заменяет песочницу: вердикт «чисто» ничего не
   гарантирует.
5. **LDR** — обфускация; мотивированный атакующий восстановит паттерны.
6. **RAR/7z** не распаковываются — проверяется только формат.
7. **CSP ослаблен для предпросмотра** (`frame-ancestors 'self' https:`).
   Для продакшена сузьте до `'none'` и вынесите CSP в заголовки хостинга.

## 8. Чеклист перед публикацией

1. В Firebase включён только Email/Password; лишние провайдеры отключены.
2. Применены `database.rules.json`; тест правил в эмуляторе пройден.
3. Включён App Check (reCAPTCHA v3) и ограничение API-ключа по домену.
4. Адрес владельца совпадает в `js/firebase-config.js` и правилах.
5. `python3 -m pytest -q` зелёный (включая паритет и UI-смоук).
6. Проверено, что Pages собирается из ветки с изменениями.
7. В репозитории нет `node_modules`, `var/`, баз и токенов.
